# 測量・インフラ点検 ドローン需要マップ

国土交通省 Project LINKS が公開する **無人航空機 飛行計画データ（2025年度）** をもとに、
**測量 / インフラ点検・保守 / 設備メンテナンス** を目的としたドローン飛行計画（申請）を
**市区町村別に集計し、地図上で可視化** する静的 Web サイトです。

「どの地域でこれらの用途のドローン活用が伸びているか」を把握するための、
建設・測量・インフラ管理事業者向けのエリア分析ツールを想定しています。

> ### ⚠️ データの性質（必ずお読みください）
> - 本マップは飛行計画の **「申請（通報）」ベース** です。**実際の飛行や活用実態を表すものではありません。**
> - 元データは紙資料のスキャン抽出を含むため、**完全性・正確性は保証されません。**
> - 位置情報は提供元で **市区町村の重心レベルに秘匿化** されています。個人や事業者の特定につながる利用はしないでください。

## できること（画面の使い方）

| 操作 | 内容 |
|---|---|
| **用途の絞り込み** | 「全ターゲット用途／測量／インフラ点検・保守／設備メンテナンス」を切り替え。地図の円とランキングが連動します。 |
| **地図の円** | 市区町村ごとの申請件数。**円が大きいほど件数が多い** ことを表します。ホバーで件数、クリックで詳細パネルを表示。 |
| **ランキング** | 都道府県／市区町村の上位を表示。クリックでその地域へズームします。 |
| **地域の詳細** | 市区町村ごとの用途構成、技能証明（一等・二等）保有率、目視外（BVLOS）・30m 未満飛行の割合、月別推移。 |
| **背景地図の切替** | 地理院タイルの「標準地図 / 衛星写真」を切り替え。 |
| **言語切替** | 画面右上で **日本語 / English** を切り替え（UI 文言・都道府県名・凡例を翻訳）。 |

### 収録範囲（2026-06 時点の生成データ）

- 対象期間：**2024年7月〜2025年6月（12ヶ月）**
- 走査した飛行計画：**約 297 万件** → うちターゲット用途 **約 60 万件** を **1,889 市区町村** に集計
- API キー不要。地図表示も含めすべてブラウザ内で完結します。

## 公開（GitHub Pages）

静的サイトのため、ビルド不要でそのまま配信できます。

- **方法A（推奨）**: 同梱の GitHub Actions（`.github/workflows/deploy-pages.yml`）が `docs/` を公開します。
  リポジトリの **Settings → Pages → Source** を **GitHub Actions** に設定してください。
- **方法B**: Settings → Pages → Source を **Deploy from a branch** にし、対象ブランチの **`/docs`** フォルダを指定。

公開後の URL はおおむね `https://<ユーザー名>.github.io/<リポジトリ名>/` の形になります。
（private リポジトリ等で Pages を使わない場合は、`docs/` 配下を任意の Web サーバーへ置くだけで動作します。）

### ローカルで開く

```bash
python3 -m http.server 8000 --directory docs
# ブラウザで http://localhost:8000/ を開く
```

## リポジトリ構成

```
pipeline/                集計データ生成スクリプト（Python）
  resources.py             配信元（CKAN）のリソース定義・恒久ダウンロードURL
  fields.py                フィールド名の正規化・出発地の都道府県/市区町村分割
  build.py                 ダウンロード → ストリーミング集計 → JSON 出力
docs/                    GitHub Pages で配信する静的サイト（これだけで動作）
  index.html               画面
  assets/app.js            ロジック（MapLibre 地図・集計表示・言語切替）
  assets/style.css         スタイル
  data/                    ← サイトが読み込む集計済みデータ（下記「出力データ」）
    municipalities.json
    prefectures.json
    meta.json
.github/workflows/       GitHub Pages デプロイ用ワークフロー
data/raw/                生 GeoJSON 等（.gitignore 対象。再生成可能なため未コミット）
```

### 出力データの仕様

サイトは `docs/data/` の 3 ファイルだけを読み込みます。第三者がこの集計を再利用する際の項目定義です。

**`municipalities.json`** — 市区町村の配列（`target` 降順）

| キー | 意味 |
|---|---|
| `name` / `pref` / `city` | 出発地（例 `大分県大分市`）／都道府県／市区町村 |
| `lat` / `lon` | 代表座標（市区町村重心・秘匿化済み） |
| `target` | ターゲット用途の申請件数（3用途の **和集合**） |
| `survey` / `infra` / `maint` | 測量／インフラ点検・保守／設備メンテナンスの件数（**重複あり**） |
| `bvlos` / `m30` | 目視外飛行／30m 未満飛行の件数（ターゲット内） |
| `lic1` / `lic2` | 技能証明 一等／二等を保有する申請の件数（ターゲット内） |
| `months` | `{ "YYYYMM": 件数 }` の月別内訳 |

**`prefectures.json`** — 都道府県ロールアップ（`municipalities.json` を集約。各用途件数 + `munis`=市区町村数）

**`meta.json`** — 生成メタ情報（出典・対象期間・`stats` 各種件数・`month_target`/`month_total` 月別合計・`blanket_threshold` 等）

## 集計データの再生成

元データは月次 GeoJSON 全 16 ファイル・合計 **約 9.5GB**（後半の月は 1 ファイルで約 1GB）。
`build.py` は **1 ファイルずつ ダウンロード → ストリーミング解析 → 削除** するため、
低メモリ・小ディスクで完走します（飛行範囲ポリゴン `geometry` は読み捨て）。

```bash
pip install ijson openpyxl
python3 pipeline/build.py            # 全12ヶ月（2024年7月〜2025年6月）
python3 pipeline/build.py --limit 4  # 先頭4ファイルのみ（動作確認用）
python3 pipeline/build.py --keep     # 生データを削除せず残す
```

成果物は `docs/data/` に上書き出力されます。

### 前処理の方針（このデータ特有の「クセ」への対応）

| # | データの問題 | 本パイプラインの対応 |
|---|---|---|
| 1 | レコードが約 297 万件と大きい | ストリーミング解析で `geometry` を捨て、市区町村集計に要約。配信は軽量 JSON のみ |
| 2 | フィールド名の表記ゆれ（末尾スペース `インフラ点検・保守 `、異体字 `機体認証(⼀種)` の `⼀` 等） | キーを **NFKC 正規化＋trim** してから照合。生キー名はハードコードしない（`fields.py`） |
| 3 | 日時の品質が低い（`飛行日時_*` に年跨ぎ等） | 月別集計は「**ファイル＝対象月**」を信頼単位とする |
| 4 | 包括申請ノイズ（業務目的フラグが過剰に立つ行） | 業務目的フラグが `BLANKET_THRESHOLD`（既定 8）以上の行を除外し、件数を `meta.json` に記録 |
| 5 | 座標の粒度差 | `出発地緯度経度`（市区町村重心・秘匿化済み）を地図の代表点に使用 |
| 6 | 「計画（申請）」であって実飛行ではない | UI に「申請ベース」と明記 |
| 7 | 欠損あり | null 安全に処理（座標欠損の市区町村は地図対象外） |

### ターゲット用途の定義

`飛行目的（業務）_測量` `_インフラ点検・保守` `_設備メンテナンス` のいずれかが `1` の行。
3 用途は同時に立ち得るため、**`target`（全ターゲット用途）は 3 用途の和集合** であり、
`survey`/`infra`/`maint` の各小計は重複を含みます。

## 使用技術

- データ処理: Python（`ijson` でストリーミング解析、`openpyxl` で仕様書参照）
- フロントエンド: 素の HTML / CSS / JavaScript（ビルド工程なし）
- 地図: [MapLibre GL JS](https://maplibre.org/) + 地理院タイル（ラスタ）
- 配信: GitHub Pages（静的）
